## 画布适配输出契约（canvas-shots/v1 · 本节优先）

> 本节为「无限画布」适配层。**与正文任何条款冲突时，以本节为准**。正文的相机预设（§4.5）、逐张具体焦段（§4.6）、人类皮肤细节句、默认负面附加项（§7）、风格基调（§4.7）全部继续有效——它们是被**投影**进机读层，而不是被删掉；人读的九张概览（世界观备注 / 📷 摄影 / 💡 灯光 / 中英双语）照原样输出，不压缩。

### 一、三处口径裁决（正文与画布冲突，一律按此）

1. **机读层只出中文一版**。正文要求每张都给 English Prompt 与中文提示词两条完整段落——人读层两条都要；机读块只放**中文压缩版**（画布下游是中文流程，`review` 质检按中文固定串判）。节点模型若偏英文（SD / Flux / MJ），把正文英文版整段贴进那个节点即可，机读块不用改。
2. **英文固定串改写成中文，不整段搬运**。`A cinematic photograph, Arri 65mm camera, Cooke anamorphic lenses, analog film stock` 压成一句「电影剧照质感：Arri 65mm 机身＋Cooke 变形宽银幕＋模拟胶片颗粒」；默认负面串压成**一条中文禁项**（见 §三）。`--sref` / `--profile` / `--ar` 一律不进机读块。
3. **画幅是节点参数，不是提示词**。默认 16:9 与正文口径一致；用户要 21:9 / 9:16 时由调用方写节点的 `aspectRatio`，提示词里不出现画幅字样。若项目已用画布 `camera` 统一机身与焦段，机读块可省掉机身串，只留本镜焦段，避免同一段光学描述被写两遍。

### 二、输出结构（人读正文之后追加机读块）

1. 人读层：世界概述 → 世界设定正文 → 关系与一致性说明 → 视觉展开（视觉设定规范 + 九张概览，或模式 B/C 的对应内容），格式与正文完全一致。
2. 文档**末尾**追加唯一一个 ```json 围栏，严格按契约 `canvas-shots/v1`（见 `docs/skill-canvas-output-contract.md` §2）：

```json
{
  "schema": "canvas-shots/v1",
  "style": "世界视觉语言一句话：主色名 + 材料 + 光 + 镜头基底",
  "locks": [],
  "shots": [
    {
      "no": 1,
      "title": "镜头 01 居民·盐工",
      "type": "image",
      "prompt": "300–600 字中文提示词",
      "locks": []
    }
  ]
}
```

3. 用户明确要求「仅设定」→ **不输出机读块**（没有要落到画布上的节点）。
4. 九张概览与 `shots` 一一对应，`no` 1–9 连续；用户减少张数或只要子集时，按 1..N 重编（契约要求连续），方面名保留在 `title` 里。扩展批次继续 10 起编号，不重排。

### 三、每镜 prompt 压缩规则（300–600 字，硬上限 800）

按顺序写成 1–2 段中文：

```
主体与瞬间（谁/什么在做什么，像被截取的一帧，不是排排站或设定表）
景别 + 机位高度角度 + 具体焦段（写出 18/24/35/50/85/135mm 这类数值，不写"广角/长焦"）
光源类型 + 来源锚点 + 方向 + 色温（天光/火光/实用光/月照；无源光不合格）
色彩与材质（主色名 + 表面处理 + 使用痕迹：磨损、开裂、烟熏、泥）
纵深主层（只写选中的一种：光分离 / 大气透视 / 遮挡递退）
质感（胶片颗粒、光学锐度、媒介；画面里有人时加一句皮肤细节）
一条禁项（按本镜风险选：无源补光 / 无介质体积光 / 数字锐化 / CG 感 / 摆拍感）
```

**丢弃**：方面标签与「世界观备注」这类元句、设定因果解释、差异表与关系图引用、跨图连续性说明（「与第三张同一文化」）、居民信念与传闻的说明性文字、英文对照、MJ 固定串与参数、平台与画幅标注。

信念与传闻可以**演成**仪式、符号、讲述、祭祀出现在画面里，但不能在提示词里被升级成客观事实。

### 四、锚点（locks）：默认不挂，只在真重复时挂

九张概览是「看一个世界」，不是「拍同一场戏」，**默认 `locks: []`**。理由很具体：画布的覆盖率口径是「每个镜头都**全部**锚点覆盖」，给世界概览挂一张人物定妆锚点，`consistency op:"lock"` 会把那张脸当参考图连进地景、动物、建筑镜头，画面反而被带歪。

只在以下情形建锚点，并在 `shots[].locks` 里逐条引用：

| 情形 | label | kind | 提示词规范（≤300 字） |
| --- | --- | --- | --- |
| 同一族群 / 同一人出现在 ≥2 张 | `锚点·居民NN 名字` | `character` | 中性背景、正面全身、平视、中性表情、柔和均匀光、无剧情动作、无遮挡 |
| 同一地点 / 建筑出现在 ≥2 张 | `锚点·场景NN 名字` | `scene` | 正面全景、15–25° 俯角，含近景地面 / 左右中景 / 纵深远景 + 光线方向与色温 |
| 标志性器物 / 机械 / 坐骑 | `道具·NN 名字` | `prop` | 单件居中、纯净背景、多面可见、比例参照（如「约等身前臂长度」） |
| 生物定版（模式 B） | `锚点·生物NN 名字` | `character` | 中性背景、结构与比例写全、多角度一致（契约 kind 只有四种，生物归 `character`） |
| 世界视觉基调 | 不建节点 | `style` | 写进机读块 `style` 或资产库 `kind:"style"` 卡片，由 `intent` 织进每镜 |

- 编号与 `character-analyzer` / `storyboard-director` **共用同一套命名空间**：`锚点·场景03` 一旦定了这个地点，后续分镜沿用同一 label，不另开号；同一地点只允许一个锚点。
- 锁定串逐字复用：同一居民的外形串在 `locks[].prompt` 里定义一次，扩展批次引用时一字不改。
- 标题铁律：不含「镜头 / 分镜 / 镜 / shot」，不以数字开头，「镜」字后面不要紧跟数字（会被当成待锁镜头或错号）。

### 五、模式 B / C 的机读形态

- **模式 B · 生物与怪物**：`locks` 给生物定版；多视图设定表可以作一张 `镜头 NN 生物设定表`（`type: "image"`，提示词写中性背景、多视图并排、比例与配色一致、无戏剧光）；栖息地静帧作为其余 shot 并引用该生物锚点。
- **模式 C · 视觉构图**：9 条构图 → `shots` 1–9，`title` 用 `镜头 NN ` + ≤10 字构图短语（`镜头 03 贴地仰拍`）；**九条全部引用同一批 locks**（场景 + 角色各一）——这正是锚点覆盖率想要形态，模式 A 反而通常不挂。
- 单批 `recipe` 上限 24 镜，超出按 25–48 继续，编号连续不重排。

### 六、执行顺序（你不直接操作画布时，把这段一起交给调用方）

```
locks 定版出图（没出图的锚点连过去也锁不住）
  → recipe 一次铺开 shots（anchorId 只定排布起点，不建连线）
  → consistency op:"lock" 带 targetIds，只锁真该锁的镜头
  → prepareGeneration（awaiting-approval）
  → 【停手】等用户在画布点「确认本批生成与费用」
  → 生成事件到达 → preview + read_image 自评
  → 不符的改 prompt 重开批次（不覆盖已验收的）
```

审批红线：只准备批次，永不提交、永不绕过确认。**不要**把人读的设定 Text 节点连到镜头——Text→Image 会把整份世界观拼进每条提示词。

### 七、自检（不输出）

- [ ] 机读块唯一、位于文档末尾、`schema` 正确；「仅设定」时没有机读块
- [ ] `shots` 与交付的概览一一对应，`title` 能被 `镜头 NN` 正则解析，`no` 连续唯一
- [ ] 每镜 300–600 字，含**具体焦段数值**、光源来源与方向、一条禁项
- [ ] 提示词里没有英文固定串 / MJ 参数 / 方面标签 / 设定解释 / 画幅字样
- [ ] `locks` 每条 ≤300 字；label 不含镜头词、不以数字开头、与正文编号一致
- [ ] 只有真重复出现的个体 / 地点才挂锚点；`shots[].locks` 全部能在 `locks[]` 找到
- [ ] 模式 C 的 9 条全部引用同一批 locks
- [ ] 单批 ≤24 镜
