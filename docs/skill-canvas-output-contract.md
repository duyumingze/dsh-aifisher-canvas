# 画布技能输出契约（canvas-shots/v1）

> 面向：任何要把「创作类产出」落到无限画布上的技能（分镜、资产、风格、提示词）。
> 目标：让技能产出**一次解析即可铺成节点**，而不是靠人手工搬运、靠模型现场编坐标和参数。

## 0. 为什么需要这一层

技能天然产出「人读的规格书」：一个镜头 13 个【标签】块、1900–3500 字。画布节点要的是另一件东西：一段 300–600 字、生成器听得懂、不含元信息的提示词。两者之间缺一层**投影**；不做这层投影，直接把规格书塞进 Image 节点，会出现四个硬问题：

1. **主体被稀释**：图像模型对长文本按权重摊薄，「主体是什么」淹没在【台词与音效】【衔接】里。
2. **元信息变噪音**：「与上一镜动作匹配」「情绪目的」「建模优先级」对生成器无意义，甚至诱导它去画别的东西。
3. **接不上批次**：recipe 一次最多 24 镜、参数键必须被模型声明，缺失信息只能靠模型即兴，一即兴就报 `INVALID` 整批失败。
4. **锁不住一致性**：画布锁脸靠「锚点节点 → connect 到每个镜头」，规格书里没有锚点概念就没有连线依据。

契约只规定**机读那一层**，人读规格书原样保留、不压缩。

## 1. 两层输出

| 层 | 形态 | 谁看 | 约束 |
| --- | --- | --- | --- |
| 人读规格书 | Markdown 正文 | 用户审稿 | 不限长度，保留技能原有格式 |
| 机读块 | 文档**末尾唯一**一个 ```json 围栏 | host / agent | 严格按 §2 schema，字段不多不少 |

机读块是唯一可解析源：agent 只读它，不去正则解析正文。

## 2. 机读块 schema

```json
{
  "schema": "canvas-shots/v1",
  "style": "全片调性一句话（含 palette / 饱和度 / 胶片 / 颗粒 / 光晕）",
  "locks": [
    { "label": "锚点·角色01 林溯", "kind": "character", "prompt": "≤300 字定妆提示词" },
    { "label": "锚点·场景02 山间破庙", "kind": "scene", "prompt": "≤300 字定版提示词" }
  ],
  "shots": [
    {
      "no": 1,
      "title": "镜头 01 河堤呐喊",
      "type": "image",
      "prompt": "300–600 字中文提示词",
      "duration": 5,
      "locks": ["锚点·角色01 林溯"]
    }
  ]
}
```

字段表：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema` | 是 | 固定 `canvas-shots/v1` |
| `style` | 否 | 全片调性；agent 可拼进每个 shot 的 prompt 前缀，也可不用 |
| `locks[].label` | 是 | 锚点节点标题，见 §4 命名 |
| `locks[].kind` | 是 | `character` / `scene` / `prop` / `style` |
| `locks[].prompt` | 是 | 定妆/定版提示词，≤300 字，中性背景、无剧情（见 §5） |
| `shots[].no` | 是 | 1–999 整数，同批唯一、连续；决定 `title` 与分镜板顺序 |
| `shots[].title` | 是 | `镜头 NN ` + ≤12 字短语；NN 与 `no` 一致、两位补零 |
| `shots[].type` | 是 | `image`（静帧/概念图）或 `video`（需运动）；分镜板只认这两类 |
| `shots[].prompt` | 是 | 见 §3 压缩规则 |
| `shots[].duration` | 否 | 仅 video；**只在确定该模型暴露时长参数时才写**，否则省略 |
| `shots[].locks` | 否 | 引用 `locks[].label`；空数组等于不锁 |

未知键一律删除：画布 `configure` 对模型未声明的参数直接 `INVALID`，一个坏键毁整批。资产类技能可以只给 `locks`，`shots` 给 `[]`。

## 3. 提示词压缩规则（300–600 字，硬上限 800）

| 必须保留 | 必须丢弃 |
| --- | --- |
| 主体 + 人数 + 正在进行的瞬间（「被截取的一帧」，不是摆拍清单） | 台词、人声细节、环境音效、音桥标注 |
| 景别 + 机位高度/角度 + 焦段 + 运镜 | 与上一镜的衔接方式 |
| 光源类型 + 来源锚点 + 方向 + 衰减（无源光即不合格） | 镜头功能、情绪目的、反规则说明 |
| 色调五层（palette/饱和/胶片/颗粒/光晕）+ 影调密度 | 自检结论、红线清单、设计步骤 |
| 纵深主层（光分离/大气透视/遮挡递退，只选一种） | 建模优先级、材质表现重点、多角度需求等制作备注 |
| 质感锚点三项（光学锐度、影调密度、媒介）+ 皮肤/焦外按需 | 「时长」「不计算时长」这类元描述 |
| 一条禁项（无源补光、物理雾滥用、数字锐化、蜡质皮肤等） | 场景要素分析表、交叉索引 |

压缩是有损的、也是故意的：规格书是给人看的全景，prompt 是给生成器的单帧指令。

## 4. 命名与排序

分镜板与一致性覆盖率共用同一套解析（`CanvasStoryboard.storyboardNumber` / `consistency.shotNumberFromTitle`）：

```
/(?:镜头|分镜|镜|shot|sh)[\s#:：·\-_]*(\d{1,3})/i   // 或标题开头「01.」
```

- 镜头节点标题必须含 `镜头 NN`，编号连续、不重排。
- 锚点节点标题 `锚点·角色NN 名字` / `锚点·场景NN 名字` / `道具·NN 名字`，**不要**在标题里出现「镜头/分镜/镜/shot」，也**不要**以数字开头——否则会被当成待锁镜头或错号。
- `锚点·角色01` 里的「角色」不触发解析，安全。

## 5. 锁定串与锚点

画布的一致性机制是「上游节点结果 = 参考图」：把定妆/定版节点 `connect` 到每个镜头，生成时自动带上。文字与图是双保险：

1. **文字锁定（逐字复用）**：同一角色的外形串在 `locks[].prompt` 里定义**一次**，每个 shot 的 prompt 里逐字复用同一段，不许改写措辞（改一个字就漂）。
2. **图锁定**：锚点节点必须**已经生成出图**再锁，没结果的锚点连过去也锁不住（覆盖率会报 `ready:false`）。
3. **全覆盖口径**：角色 + 场景两个锚点时，只接角色等于没锁全；覆盖率按「全部锚点都被引用」才算 covered。
4. 定妆提示词规范：中性灰/纯色背景、正面全身、平视、中性表情、柔和均匀光、无剧情动作。需要多角度就拆成 `锚点·角色01 林溯-正面/-侧面/-背面` 三张，全部接上。

## 6. 分批

- 单次 `recipe` 上限 **24** 镜（`MAX_SHOTS`），超出按 1–24、25–48… 分页，编号连续不重排。
- 每批一次 `edit`；`anchorId` 指规格书 Text 节点或上一批末节点，只用来定排布起点，**不建连线**。
- 不要把规格书 Text 节点连到镜头：Text→Image 的连线会把上游正文拼进每条 prompt，整份剧本污染全部镜头。

## 7. 执行顺序

```
locks 定妆/定版节点（生成出图）
  → recipe 一次铺开 shots
  → connect 锚点 → 每个镜头（可省略：让用户在面板上点「锁定」）
  → prepareGeneration（返回 awaiting-approval）
  → 【停手】等用户在画布点「确认本批生成与费用」
  → 生成事件推送 → preview 取本地路径 → read_image 自评
  → 不符的镜头改 prompt 后重新 prepare（新批次，不覆盖已验收的）
```

审批红线不变：`canvas_control` 只准备批次，永不提交、永不绕过确认。

## 8. 自检（技能侧，不输出）

- [ ] 机读块只有一个、在文档末尾、`schema` 正确
- [ ] 每镜 prompt 300–600 字，无 §3 丢弃项，含光源来源与一条禁项
- [ ] `no` 连续唯一、`title` 能被正则解析、锚点标题不含镜头词
- [ ] 所有 `shots[].locks` 都能在 `locks[]` 里找到
- [ ] 单批 ≤24 镜
- [ ] 没有编造参数键（`duration` 只在确定支持时写）
- [ ] 角色外形串跨镜头逐字一致

## 9. 演进

改动 schema 时升 `schema` 版本（`canvas-shots/v2`），并同步：
`docs/skill-canvas-adapter-storyboard.md`、`docs/skill-canvas-adapter-assets.md`、
`docs/skill-canvas-adapter-worldbuilding.md`、`scripts/build-canvas-skills.mjs`。

## 10. 已知的接入方

| 技能 | 机读形态 | 锚点 |
| --- | --- | --- |
| `storyboard-director` | `locks` + `shots`（每镜一图/视频） | 引用角色/场景锚点 |
| `character-analyzer` | 只有 `locks`（`shots: []`） | 产出 `锚点·角色NN` / `锚点·场景NN` / `道具·NN` |
| `worldbuilding-moke` | 九张世界概览 → `shots` 1–9 | **默认不挂**，只在同一居民/地点重复出现时挂；编号与上面两个技能共用 |

`worldbuilding-moke` 的源件来自 MOKE 藏经阁（name 是 `MOKEAIGC-V017` 这类版本号），由
`build-canvas-skills.mjs` 的 `name` 覆盖归一成 `worldbuilding-moke`，跨版本稳定。
